# Rendering in Next.js: Server vs Client Components

Next.js introduces a powerful hybrid model combining Server Components and Client Components to deliver optimized performance, improved SEO, and excellent user experience.

---

## ![Component Comparison](./f4c49c9d-74cb-488b-85b9-668582d412ea.png)

This chart visually compares capabilities of Server and Client Components:

| Task / Feature                                      | Server Component ✅ | Client Component ❌ |
| --------------------------------------------------- | ------------------ | ------------------ |
| Fetch data                                          | ✅                  | ❌                  |
| Keep sensitive info on server (API keys, tokens)    | ✅                  | ❌                  |
| Keep large dependencies on server / reduce JS size  | ✅                  | ❌                  |
| Add interactivity (onClick, onChange, etc.)         | ❌                  | ✅                  |
| Use state and lifecycle (useState, useEffect, etc.) | ❌                  | ✅                  |
| Use browser-only APIs (localStorage, window, etc.)  | ❌                  | ✅                  |
| Use hooks that rely on browser/state/effects        | ❌                  | ✅                  |

## Rendering Strategies

### 1. **Client-Side Rendering (CSR)**

* The browser renders content using JavaScript.
* Good for dynamic SPAs, but:

  * Poor SEO (initial HTML is empty).
  * High JS bundle size.
  * Slower time to interactive.

### 2. **Server-Side Rendering (SSR)**

* Server renders full HTML before sending it to client.
* Benefits:

  * Better SEO.
  * Faster first contentful paint.

#### SSR Process:

1. Server renders page HTML.
2. HTML sent to browser.
3. React hydrates page: attaches events, hooks, etc.

**Drawbacks:**

* Hydration delays.
* All data must be fetched before rendering.
* Full JavaScript still needs to be sent.

### 3. **Static Site Generation (SSG)**

* Pages are rendered at build time.
* Great for static content (blogs, docs).

## React Suspense in SSR

**Improves loading behavior in SSR via HTML streaming.**

### Features:

* Server streams HTML in chunks.
* Components render as they load.
* Supports fallback UI (spinners, skeletons).

```tsx
import { Suspense } from 'react';
import UserProfile from './UserProfile';
import Loading from './Loading';

export default function Page() {
  return (
    <Suspense fallback={<Loading />}>
      <UserProfile />
    </Suspense>
  );
}
```

### Benefits:

* Faster Time-to-Content (TTC).
* Reduces perceived loading.
* Prevents blank screens.

### Challenges:

* Requires component structure planning.
* Hydration still blocks interactivity initially.

## React Server Components (RSC)

React 18+ introduces **Server Components**, changing how apps are rendered.

### ✨ Server Components

* Run only on the server.
* Never sent to client.
* Can fetch data, access databases securely.
* Cannot use `useState`, `useEffect`, or handle interactions.

```tsx
// Server Component (default)
import { fetchProducts } from '../lib/products';

export default async function ProductList() {
  const products = await fetchProducts();

  return (
    <ul>
      {products.map((product) => (
        <li key={product.id}>{product.name} - ${product.price}</li>
      ))}
    </ul>
  );
}
```

### ✨ Client Components

* Require `'use client'` directive.
* Run in the browser.
* Handle interactions, state, effects, browser APIs.

```tsx
'use client';
import { useState } from 'react';

export default function Counter() {
  const [count, setCount] = useState(0);

  return <button onClick={() => setCount(count + 1)}>Clicked {count} times</button>;
}
```

## Final Thoughts

### Server Components:

* ✅ Smaller bundles
* ✅ Secure data access
* ✅ Built-in streaming support
* ❌ No interactivity

### Client Components:

* ✅ Interactivity and state
* ✅ Access browser APIs
* ❌ Must be hydrated
* ❌ Larger bundle sizes

> **Next.js empowers you to combine both Server and Client Components** where appropriate to maximize performance, user experience, and security.
